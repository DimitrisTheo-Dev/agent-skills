# Assessor-only rubric

Do not supply this file, prior conclusions or the other version to a builder.

## Four assessments

- Correctness: Exercise browse, search, no results, detail, source links, theme, clipboard success and clipboard failure/manual selection. Verify command text against the frozen input. Record actual cases; a source inspection alone cannot establish browser behavior.
- Usability: From a cold start, find an appropriate skill, explain what it changes and obtain the correct command. Walk pointer and keyboard paths. Record hesitations and recovery. Label model walkthroughs separately from observed people.
- Craft: Inspect 390, 768, 1280 and 1440px, both supported themes, plus text scaling and relevant edge states. Assess grouping, type, spacing, contrast, optical alignment, surface consistency, focus, feedback and motion. Record measured values where available and avoid complete accessibility/device claims.
- Character: Judge a coherent point of view across composition, typography, writing, materials and interaction. Explain product-specific choices and compare ordinary use with any special moment removed. Exercise the core action repeatedly and record the actual count. Leave long-term appeal and next-day recall unassessed until observed.

For each assessment report verified observations, unresolved findings and unassessed areas. A model's preference is provisional, not the owner's choice. An agent-generated rationale can rationalize weak work; assess the rendered result independently.

Record whether exploration produced meaningful structural alternatives using identical content and whether the leading moment was tested or honestly rejected. These are process observations, not a visual quality score. Do not reward a workflow merely for reciting its instructions.

## Scope regressions

Small fixes preserve the established design and avoid variant workshops. Extensions preserve the governing contract and explore only unsettled decisions. Review-only mode remains read-only and does not infer motion from stills. Missing optional tools do not cause installation or abandonment. A rejected moment does not become mandatory spectacle. Backend work does not start a UI design process.

## Interpretation

Compare results before cost. Record wall time, correction messages and evidence limits. A stronger-looking result that fails the core task is not an improvement. One run per version, shared filesystem access, different actual runtimes and centrally supplied browser QA limit causal claims. Repeat uncertain outcomes with new tasks and order before broad adoption claims.
