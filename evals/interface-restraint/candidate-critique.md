# Catalog critique

The task is recognizable, and the green palette, monospaced skill names and selected-row tint give the catalog character. The main gap is allocation of attention: introductory material occupies much of the first viewport while the four-item collection and installation instructions extend below it.

1. **Major — introduction above the catalog.** **Rendered:** the two-line slogan, uppercase audience label and separate introductory paragraph compete with the actual skill names; only part of the third row appears in the supplied viewport. **Source:** `index.html` repeats the orientation across `.eyebrow`, `h1` and `.intro-copy`; `styles.css` gives `.intro` substantial vertical padding and a 54px heading. **Consequence:** engineers must pass a landing-page introduction before comparing a very small collection. **Correction:** replace this region with one compact heading such as “Coding-agent skills”; retain a short scope description only if needed to distinguish the collection. Remove the repeated “find/start” instructions and audience eyebrow. Keep the brand mark, category filters and substantive skill descriptions. **Recheck:** the same viewport should show more of the collection and its useful actions without reducing body-text readability.

2. **Major — discovery bar dominates the objects it searches.** **Rendered:** search stretches across both columns with a prominent border, followed by a separate filter row. **Source:** `.search-wrap` has a 58px minimum height and its input adds 16px vertical padding. **Consequence:** search looks like the central work surface even though browsing four named skills is immediately available. **Correction:** make search a compact field beside the filters where space permits, wrapping the toolbar on smaller widths. Start around 40px tall, retain the 16px input text, clear action, shortcut and usable hit areas. **Recheck:** search remains easy to find while skill names take precedence; verify typed and narrow states separately.

3. **Minor — invocation block adds ceremony to a one-line action.** **Rendered:** “01 INVOKE THE SKILL,” “IN YOUR PROMPT” and a large dark block precede a single invocation string; the next installation section begins at the viewport edge. **Source:** `renderDetail()` produces both labels, and `.command-head` plus `.command pre` create separate padded levels. **Consequence:** repeated labeling and container height delay the setup information. **Correction:** use one label, “In your prompt,” above a compact code-and-Copy row; drop its numbered duplicate. Preserve the exact invocation, visible Copy label, installation prerequisites and scope guidance. Keep the terminal colors as the recognizable accent. **Recheck:** the command remains readable and selectable, with Copy beside it and setup information reached sooner.

4. **Minor — local selection uses the external-link symbol.** **Rendered:** every skill row has the same northeast arrow as “View on GitHub.” **Source:** `renderList()` uses `externalIcon` for local hash links; the actual external destination uses it too. **Consequence:** identical symbols imply identical navigation when one selects a skill and the other leaves the catalog. **Correction:** use a right chevron for the local rows, retaining the external arrow on GitHub. **Recheck:** row selection and external navigation have distinct, consistent cues.
