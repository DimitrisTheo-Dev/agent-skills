# Catalog critique

The green palette, monospace skill names and selected-row treatment already give this utility character. Preserve them. The largest gap is how much space precedes the useful catalog.

1. **Major — Intro above search and catalog.** **Rendered:** the two-line slogan and supporting introduction dominate the upper screen; the collection begins around halfway down the supplied capture, and the installation command is below its bottom edge. **Source:** `index.html:4` and `.intro`, `h1`, `.topbar` in `styles.css` establish the separate hero and generous vertical spacing. **Consequence:** engineers must pass a promotional introduction on every visit before comparing or using skills. **Correction:** condense this into a compact title and one scope sentence directly above search; reduce the intro/header spacing before reducing useful text sizes. Retain the skill count and subject coverage. **Recheck:** at the supplied desktop dimensions, confirm the collection and selected skill's commands appear substantially earlier without crowding search.

2. **Major — Numbered invocation and installation sections.** **Rendered:** “01 Invoke the skill” precedes “02 Install from your checkout.” **Source:** `app.js:17` explicitly numbers these as steps; the extracted `skills.js` setup text requires a repository checkout and an existing skills directory. **Consequence:** the numbering suggests invocation is the first setup step, although someone installing the skill needs its prerequisites first. **Correction:** retain fast access to invocation, but use unnumbered task labels such as “Use in your prompt” and “Install locally”; keep the checkout prerequisite and existing-installation behavior beside the install command. **Recheck:** inspect both first-install and already-installed reading paths, including the lower content not visible in this capture.

3. **Minor — Catalog row density.** **Rendered:** only two complete skills and part of a third fit in the visible list; every row gives name, description and category separate vertical bands. **Source:** `.skill-row` has 22px vertical padding, descriptions have 12px top/bottom margins, and `.row-category` occupies another line. **Consequence:** the four-item collection takes more scanning and scrolling than its content warrants. **Correction:** reduce row padding and internal gaps, and place the short category beside the name where it fits. Preserve the task descriptions and allow wrapping at narrower widths. Keep the full row clickable. **Recheck:** inspect all four real names and descriptions at the same viewport and near the responsive breakpoint; do not obtain compactness through clipped text or smaller essential labels.

4. **Minor — Skill-row destination icon.** **Rendered:** each row uses the same northeast arrow as “View on GitHub.” **Source:** `app.js:8,15,17` reuses `externalIcon` for internal hash navigation and the external GitHub link. **Consequence:** the catalog suggests that selecting a skill opens an external destination, weakening the otherwise familiar list/detail interaction. **Correction:** reserve the northeast arrow for GitHub; use a simple chevron for internal selection or omit the row arrow while retaining hover, focus and selection cues. **Recheck:** compare the list and GitHub affordances together, then verify keyboard selection still exposes a clear current item.
