# Ten typography directions

Choose by task and letterform needs. These profiles specify relationships, not a shopping list or randomized style menu. Use installed/licensed families first. An example family category is not proof a particular font supports the required language.

| Direction | Display and utility relationship | Useful context | Reject or adapt when |
| --- | --- | --- | --- |
| Quiet utility | System or neutral sans throughout; compact size steps; medium weight marks action and hierarchy | Frequent operation, settings, search, command surfaces | The product needs expressive storytelling that this leaves anonymous |
| Dense analytical | Compact readable sans; strong numeral differentiation; tabular figures only in aligned data | Tables, finance, observability, comparison | Narrow forms or tiny text make values hard to distinguish |
| Humanist clarity | Open apertures, distinct glyphs and comfortable body rhythm; modest display contrast | Instruction, public services, forms, mixed reading ability | A selected family fails real scripts or relies on undersized labels |
| Editorial serif | Expressive serif headlines with quiet sans controls; readable serif or sans prose | Essays, culture, craft or considered storytelling | Serif display dominates a high-frequency operating screen |
| Reading first | Text family optimized for paragraphs; subdued navigation; headings form a clear outline | Documentation, research, long lessons | The screen's real job is rapid comparison rather than reading |
| Technical precision | Sans for instructions; mono for code, identifiers or stable structured data | Developer products, engineering tools, code teaching | Monospace spills into long paragraphs or inaccessible narrow columns |
| Warm rounded | Soft forms and selected heavier headings; restrained, readable utility roles | A friendly coaching or creative product with matching voice | Rounded type infantilizes the subject or reduces information density |
| Condensed display | Condensed face for short large headlines; normal-width text and controls | Posters, sport, media and compact expressive titles | Long headings, unsupported scripts or small labels lose readability |
| High-contrast display | Delicate/contrasting display forms at large sizes; robust utility face below | Luxury, arts or dramatic editorial treatment | Thin strokes fail at actual size or the aesthetic undermines trust |
| Bold vernacular | A distinctive chunky/display face in short signature phrases; simple text for operation | Independent entertainment, playful tools, community identity | Every label performs personality and the interface becomes exhausting |

A single family can cover multiple profiles through size, width and weight. Two families need complementary roles. Neither one family nor two weights is a universal quality rule.

## Pick with evidence

Use the same realistic heading, long title, paragraph, label and numeric sample. Compare recognition, density, rhythm and product voice. Mention the rejected candidate's concrete weakness, such as unfamiliar glyph shapes at small sizes or a display face consuming too much vertical space.

Choose actual families only after inspecting available assets and terms. If using an external source, verify its current license, supported scripts, weights and delivery costs before adding it. A fallback should preserve usable wrapping and hierarchy; it need not imitate every detail. Avoid a visible family mismatch within a word when language glyphs fall back.

For a Greek/English product, include accented Greek, mixed Latin identifiers, dates and real names in the specimen. For RTL or other supported scripts, inspect direction, punctuation and appropriate line-height. Do not transplant Latin tracking or uppercase styling mechanically.

## Starting hierarchy

Use these only when no governing system exists. Values are illustrative CSS pixels at a 16px root; implement relative sizing where appropriate and verify enlargement.

| Role | Operating interface starting point | Reading/editorial starting point |
| --- | --- | --- |
| Page title | 24–32 / 1.15–1.3 line-height | 32–48 / 1.1–1.25 |
| Section heading | 18–22 / 1.25–1.4 | 24–32 / 1.2–1.35 |
| Body | 15–17 / 1.4–1.6 | 17–20 / 1.5–1.7 |
| Label/control | 14–16 / 1.2–1.4 | 14–16 / 1.2–1.4 |
| Supporting metadata | 12–14 / 1.35–1.5 | 13–15 / 1.35–1.5 |

Read actual letterforms and use conditions. These ranges do not authorize tiny essential information, force five sizes or prescribe a giant marketing heading inside an app. A landing headline may need another scale; a dense table may need another rhythm. Pick concrete tokens rather than leaving implementation as ranges.
