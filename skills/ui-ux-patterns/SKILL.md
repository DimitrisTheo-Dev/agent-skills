# UI UX Patterns

Own how information and actions are organized. Improve recognition, effort, confidence and time to value through explicit conditional choices. Color and motion cannot repair a task represented by the wrong structure. Review and brief modes leave project files unchanged unless an artifact is requested.

## Procedure

1. **Read the task.** Identify the person, outcome, frequency, content volume/variation, decision attributes, input effort, risk and device constraints. Trace the existing journey and terminology. Separate user evidence, observed behavior and assumptions. Finish with the most important source of effort or confusion.
2. **Choose a representation.** Read [pattern decisions](references/pattern-decisions.md). Match the task to at most two plausible structures. Evaluate both the useful condition and countercondition. Keep the current structure if no alternative solves an observed problem. Do not automatically convert lists into cards or forms into wizards.
3. **Sketch the journey with real content.** Specify information order, main action, secondary access, relevant states and narrow-screen composition. For a substantial unsettled direction, compare candidates using the same content and data. Use the parent workflow's renders. For established flows, prototype only the unresolved decision.
4. **Operate the decision.** Follow [flow validation](references/flow-validation.md). Check finding, choosing, completing, returning and recovering. Test realistic volume and long/missing data. Compare task effort and clarity, not the attractiveness of empty containers. Preserve semantics, keyboard routes and existing business behavior.
5. **Return a concrete choice.** Record the selected structure, enabling conditions, rejected alternative, tradeoff, responsive behavior and observed/unverified evidence in the shared design contract when in scope. Describe what would make the decision change. Return unresolved geometry, type or feedback needs to their owners. The parent workflow owns final review.

## Completion

The user can tell what the page is for, identify the next useful action, see decision-relevant information, complete the main path and recover without losing work. A prettier collection or shorter-looking form is not proof of lower effort.
