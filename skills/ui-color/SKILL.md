# UI Color

Make color explain the product and give it character. Own palette construction, role mapping and contrast evidence. Leave typography, layout and motion to their owners. Work within the requested brief, review or implementation mode; review does not change files.

## Procedure

1. **Read the context.** Inspect existing tokens, supported themes, real imagery, data/status needs and the current design contract. Identify the screen's job and desired emotional register. Preserve approved colors unless an observed problem or requested rebrand warrants change. Finish with the color decision that is actually unresolved.
2. **Construct a direction.** For a new identity, consult [palette constructions](references/palette-constructions.md). Select at most two plausible constructions using content and brand reasons; adapt hues rather than picking a fashionable swatch set. A construction is an option, never a required theme. A narrow contrast repair needs no alternatives. Finish with a proposed hierarchy of surfaces, text and accents.
3. **Put colors in context.** Apply proposals to the same representative screen or small screen fragment with real text, imagery and a selected/error state. Compare area distribution, primary-action visibility, state meaning and compatibility with the type/material direction. Reuse the parent workflow's direction renders. Do not create a separate palette presentation unless requested. Pick a direction and explain its strongest reason and tradeoff.
4. **Resolve the system.** Use [roles and verification](references/roles-and-verification.md). Specify actual values in the existing token source for relevant themes and states. Distinguish brand, action, selection, focus, status and data roles even when some share a value. Check actual foreground/background pairs, not a swatch's reputation. Complete the affected role map and its contrast evidence.
5. **Return the decision.** Update only the color section of the shared design contract when artifacts are authorized. Record selected construction, product-specific hue rationale, area distribution, semantic tokens, measured pairs, exceptions and unresolved checks. In a brief, supply proposed values and mark unmeasured claims. In review, report findings in the response. Let the parent workflow run the final quality gate once.

## Completion

The action hierarchy survives realistic content and imagery; status remains understandable without hue alone; affected theme/state pairs are checked; approved colors remain consistent. A contrast pass does not establish an appealing palette. A visually appealing palette does not establish contrast.

For source boundaries and measurement requirements, see [sources](references/sources.md).
