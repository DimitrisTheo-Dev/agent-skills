CORE CHOICES
- Unclear feature inside a repository: grill-with-docs. Resolve scope; cap the initial question round. It uses grilling and domain-modeling.
- Idea clarification outside a repository: use the intake procedure here; grill-me is optional if actually installed.
- Ambiguous terms or roles: domain-modeling. Define the terms affecting this change.
- Interface or module design: codebase-design. Prefer a simple caller contract.
- Defined behavior: tdd. Agree the meaningful testing boundary and build in small behavior steps.
- Difficult reproducible failure: diagnosing-bugs. Find evidence before fixing.
- One unsettled UI/state decision: prototype. Its result answers a question; check what must be hardened before final delivery.
- Finished code: code-review. Its documented default uses a committed range and a supplied base. A scope override must be explicit and honored; otherwise snapshot the intended work before review. Include new files.
- Changed UI: interface-review. It uses better-interface and relevant better-* domain rules. Preserve those supporting directories.
- UI intent: local vibe-ui, if its content is available. Read it, then use the judgment principles in the quality guide. Do not claim this bundle contains the exact original.
- Sensitive data/auth flow: local vibe-security where available, plus applicable checks from the quality guide.
- SQL/Postgres work: supabase-postgres-best-practices when installed. It is a database guide, not evidence that Supabase is the chosen platform.
- Browser/frontend detail: modern-web-guidance only for the specific concern and actual runtime.
- Context transfer: handoff when the session needs a durable summary.
