CORE CHOICES
- Unclear feature inside a repository: grill-with-docs. Resolve scope; cap the initial question round. It uses grilling and domain-modeling.
- Idea clarification outside a repository: use the intake procedure here; grill-me is optional if actually installed.
- Ambiguous terms or roles: domain-modeling. Define the terms affecting this change.
- Interface or module design: codebase-design. Prefer a simple caller contract.
- Defined behavior: tdd. Agree the meaningful testing boundary and build in small behavior steps.
- Difficult reproducible failure: diagnosing-bugs. Find evidence before fixing.
- Unsettled UI/state decisions or Shape exploration: prototype when its actual instructions are accessible. Compare directions on identical content and prototype the strongest moment hypothesis; otherwise use disposable routes in the existing stack. Retain evidence and retire only the throwaway code you created.
- Finished code: code-review. Its documented default uses a committed range and a supplied base. A scope override must be explicit and honored; otherwise snapshot the intended work before review. Include new files.
- Implemented UI before handoff: ui-quality-gate when installed. It owns ordered inspection, evidence and repair/recheck; vibe-ui owns design corrections. For a narrow fix, review its component and affected neighbors/states. Backend-only work skips this route. If unavailable, use Quality and Design and Creative Quality and name unverified areas. interface-review is an optional specialist, not a duplicate competing gate.
- Direction, implementation craft and character review: vibe-ui when accessible. Select brief, build or review mode to match the current task. During assessment, use review mode with an independent worker when permitted; otherwise label self-review. Keep correctness, usability, craft and character distinct.
- Color ramps, contrast and gamut: better-colors when accessible; otherwise inspect computed pairings directly.
- Interface copy, empty states, errors and voice: product-ux-writing when accessible. For persuasion and page narrative, landing-page-design when accessible.
- Fine interface details or motion: selectively consult make-interfaces-feel-better or an Emil specialist when accessible and relevant. Read Creative Quality and the source caveats first; retain the product contract and treat numeric recipes as hypotheses. Do not load the entire upstream collection or install tools merely to complete this route.
- Sensitive data/auth flow: local vibe-security where available, plus applicable checks from the quality guide.
- SQL/Postgres work: supabase-postgres-best-practices when installed. It is a database guide, not evidence that Supabase is the chosen platform.
- Browser/frontend detail: modern-web-guidance only for the specific concern and actual runtime.
- Context transfer: handoff when the session needs a durable summary.
